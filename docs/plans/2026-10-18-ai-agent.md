# AI agent plugin: design and work packages

Date: 2026-10-18. Builds on the decisions in `2026-10-18-roadmap.md` ("AI agent:
bring your own key"). Facts were verified on 2026-10-18 against the Anthropic
docs, the MCP spec (2026-07-28), crates.io and vendor READMEs; unverified items
are marked.

## Decisions

**Confirmed by the owner, 2026-10-18:** providers are native first-party code in
v1 (WASM providers wait for a streaming plugin interface); build order is the
foundation packages WP1 to WP3 first.

- **Native first-party plugin `manang-agent`**, not WASM, in v1. The WASM `http`
  interface has no streaming (request/response with body and time caps), so
  providers cannot be sandboxed WASM plugins until `manang:plugin` 0.3.0 adds a
  streaming interface. They are still registered like plugins (deviation from
  "providers are plugins" in the roadmap: flag to the owner).
- **In-house provider client**, rustls only, behind our own `HttpTransport`
  trait: one Anthropic Messages adapter, one OpenAI-compatible adapter (Chat
  Completions; Responses mode later). Covers Claude, Ollama, llama.cpp, LM
  Studio, vLLM and company gateways. Generic crates (`genai`, `async-openai`,
  `rig-core`) flatten what we need: raw content blocks (thinking signatures must
  be replayed byte-exact), cache breakpoints, request ids, usage. SSE parsing is
  about 60 lines; own it. `cargo tree -p manang | grep -iE "openssl|native-tls|harfbuzz"`
  must stay empty.
- **Default model `claude-sonnet-5-5`**, `claude-haiku-5-5` for cheap tasks,
  Opus 5.5 and Fable 5.1 selectable. Constraints from the API docs: no
  assistant prefill; `tool_choice` any/tool is rejected on the 5.5 family and
  Fable 5.1 (only auto/none), so never rely on forced tool calls; adaptive
  thinking cannot be disabled on Opus/Fable; keep history append-only (caching
  and thinking-block binding).
- **Writes are proposals.** A write tool returns a proposal (`text_edit` or
  `scene_patch`), never a mutation; the user accepts it as one undoable
  transaction. No direct-write, delete or rename tools in v1.
- **Risk class per tool**, declared in the manifest and enforced by the host
  (never trusted from the model): `read`, `propose`, `network`, `exec`. A tool
  runs as `kernel.invoke` under the owning plugin's capabilities; the agent has
  none of its own. Gates in order: plugin capabilities, project policy
  (`.manang/agent/policy.toml`), enterprise policy, approval rule.
- **Keys in the OS keychain only** (`keyring` 4.x with `keyring-core` and a
  per-platform store crate). Do not enable the dbus store's `vendored` or
  `crypto-openssl` features (AGENTS.md 7.4). Prefer the zbus Secret Service
  store with `crypto-rust` (pure-Rust claim unverified: spike with `cargo tree`).
  Headless Linux fallbacks: kernel keyring, then an in-memory session key with a
  clear notice. No home-made encrypted file. Keys never reach TOML, logs,
  transcripts or the audit log.
- **MCP:** expose the same `kernel.agent-tools` list as an MCP **server** after
  the tool contract lands (official `rmcp` 3.5.x, stdio through a small helper,
  no open HTTP port); MCP **client** later, off by default, forbiddable by
  policy.
- **Streaming and threads:** Tokio only for HTTP streaming, cancellation and the
  event channel (`CancellationToken`; dropping the stream closes the
  connection); CPU-bound tool work goes to Rayon through the kernel.
  `tauri::ipc::Channel<AgentEvent>` per session; large payloads over the binary
  path.
- **Storage:** `.manang/agent/sessions/<id>/{transcript.jsonl, audit.jsonl,
  meta.toml}` (raw provider blocks; excluded from git by default), policy in
  `.manang/agent/policy.toml`, provider config without keys in the user config
  dir.

## UX (one panel, three entry points; no new top-level noun)

1. Selection actions (rewrite, shorten, translate, explain) as an inline diff in
   the editor: removed text dim and struck through, inserted text in Sage, no
   shadows or rounded corners; the accept button is the view's single lime
   action.
2. "Fix with AI" on a Problems entry (sends the diagnostic and nearby lines only).
3. An Agent view as a tab inside Output (or a drawer), not a sixth side view:
   context chips (default: selection only) with token sizes, model and cost
   line (labelled estimate), Stop, "Preview what will be sent" (exact payload).

**Figures:** the diff is a scene diff on the canvas (added nodes in Sage outline,
modified nodes with a dashed ghost of the old position, removed nodes struck
through) with a per-op list and checkboxes; accept applies one undoable patch.
Requires stable node ids and a patch type in the figure studio's tool contract.

## Safety and privacy

Document text, `.bib` abstracts and fetched pages are untrusted data, delimited
in the prompt and never placed in system or tool-definition positions. Blast
radius is limited structurally: injected text can only produce a reviewable
proposal or a read of in-scope files. Network tools use an allowlist; a fetched
page cannot extend it. Approvals: read in scope auto; propose auto; network to
an allowlisted host auto after first-use consent per provider; other hosts ask;
exec ask once per session. Append-only audit log (provider, model, request id,
payload hash and payload, tool calls, approvals, usage). Optional redaction with
a visible diff. Offline switch allows only loopback (resolve the address; do not
trust a string prefix). Policy keys: `ai.enabled`, `ai.allowed_providers`,
`ai.base_url` (locked), `ai.require_audit_log`, `ai.allow_mcp_client`,
`ai.max_context_tokens`; user and project settings may only tighten. First-use
consent states what is sent and where.

## Features in order

1. Writing assistant on a selection (structured output; reject proposals that
   break `\cite{}`, `@key`, math, labels or markup balance, checked with the
   existing parsers).
2. Fix compile errors as a diff, closed loop: apply to a scratch copy, recompile
   on Rayon, show only if the diagnostic count drops (two retries).
3. Citation and claim checking on `citations.verify` (never invents entries).
4. Figure from a description (through the figure agent tools).
5. Mermaid generation (validate, then block or shapes).
6. Prompt to slides (needs templates).
7. Document Q&A over `manang-search` with anchored citations.
Tests use a recorded-cassette mock provider; live evals are opt-in
(`MANANG_EVAL_LIVE=1`).

## Work packages (disjoint files, in dependency order)

- **WP1 `crates/manang-agent-core`** (no deps; must build for wasm32): `Provider`
  trait, lossless `ContentBlock`, events, usage and price table, policy merge
  (tighten-only), audit and transcript JSONL, redaction, `MockProvider`.
  proptest (policy never loosens, transcript round-trip), insta snapshots.
- **WP2 `crates/manang-agent-providers`**: Anthropic and OpenAI-compatible
  adapters, SSE parser, retry with `retry-after`, cancellation, request-id
  capture, cache breakpoints, `HttpTransport` (reqwest rustls, proxy from
  settings). Mock SSE server tests, mid-stream error, 429/529, cancel; fuzz the
  SSE parser (60 s cap).
- **WP3 `crates/manang-keystore`**: `KeyStore` trait, platform stores,
  fallbacks, `secrecy` wrapper; commands `agent.key.set|status|clear` (never
  return the key).
- **WP4 `crates/manang-agent` + UI** (needs WP1-3 and the figure agent-tool
  contract): orchestrator, approvals, tool dispatch, event channel, commands
  `agent.start|cancel|approve|apply_proposal|reject_proposal|preview_request`;
  selection diff, Problems action, Output tab view, Settings section, project
  opt-out; features 1-2 first.
- **WP5 later:** `manang-mcp` (rmcp stdio), features 3-7, eval harness.

## Risks and unknowns

Provider API churn (isolate in adapters, cassette per behaviour); the zbus
keyring store's pure-Rust claim; WASM providers blocked on a streaming WIT
interface; the tool contract needs risk class, `scene_patch` proposals with
stable ids, deterministic tool order (cache hits) and a change notification;
prompt injection is limited, not solved; cost display is an estimate; local
models vary in tool-calling quality (gate loops behind a capability flag);
unverified: reqwest 0.13 rustls feature names, Anthropic tool-name length limit
(`^[a-zA-Z0-9_-]{1,64}`), `genai` wasm32 and cancellation support.

## Web version **(decided: after the desktop core, web-capable design from now)**

* The kernel and the plugins whose logic does not need the operating system
  (editor, Typst, Markdown, writing, figure, citations, search over provided
  files) must compile to `wasm32-unknown-unknown`. OS access stays behind
  interfaces: file storage, network (`HttpClient`, as in citations), process
  spawning (LaTeX system backend, git writes), so a browser implementation can
  replace them.
* Typst runs in the browser from the same crate. LaTeX in the browser needs a
  WebAssembly TeX; the desktop fallback for users without TeX is still open:
  BusyTeX (WebAssembly TeX Live), Tectonic, or others, pending research
  (licences, engines, package download and offline use, speed, memory).
* Storage on the web: the browser's private file system (OPFS) or a real
  folder through the File System Access API where available.

## Collaboration: git-based first **(decided)**

Asynchronous collaboration through git, no server:

* Source control view (status, stage, commit, branches, sync) as the base.
* Readable merges: conflicts shown per file with a side-by-side resolver;
  three-way merge for Typst, LaTeX and Markdown text.
* Comments and suggestions stored in the project as plain files (for example
  `.manang/comments/*.toml`) so they travel with git and survive offline;
  anchored to text positions with a resilient anchor (quote plus context).
* Review mode: suggestions shown inline, accept or reject, author and time.
* Share: "Publish to a git remote" helper and clear status of what is pushed.
* Real-time co-editing came later, on a CRDT: Loro was chosen over `yrs` and
  Automerge (ADR 0013), over an encrypted relay that sees only ciphertext;
  peer-to-peer is not built. See `2026-10-20-live-collab-v2.md`.

## Sync

* Git sync from the Source control view (`git.sync`), only on user action.
* Folder sync tools (Syncthing, Dropbox, iCloud) already work because projects
  are plain folders; the app must handle external changes gracefully (the
  project watcher exists; conflict prompts for open, unsaved files are needed).
* Settings sync across devices: optional, later.

## AI agent: bring your own key **(decided)**

* Providers are plugins. Claude is the default provider; others (and local
  models, for example through Ollama) can be added. Nothing is sent anywhere
  until the user configures a provider and accepts what is shared.
* API keys stored in the operating system keychain, never in project files or
  settings TOML.
* Features, in order: writing assistant on a selection (rewrite, shorten,
  translate, explain an error); compiler self-healing as a reviewable diff;
  citation and claim checking (built on `citations.verify`); prompt to
  document in a template; prompt to slides.
* Every AI change is a diff the user accepts; no silent edits.
* Plugins expose tools to the agent through the kernel's `register_agent_tool`
  hook, so third-party document types (docx, figures) become agent-drivable.
* Cost and privacy controls: per-request preview of what is sent, token and
  cost display, per-project opt-out.
* Engineering: agent orchestration in Rust (Tokio for streaming I/O), streamed
  tokens to the UI over a Tauri channel, cancellable requests.

## Reference library: our own, no Zotero dependency **(decided)**

* **One user library** per user **(decided)**: a configurable folder that may
  live inside an Obsidian or Logseq vault. Projects cite from it and get a
  generated `references.bib` / CSL-JSON containing only the cited entries, so a
  project still compiles and travels on its own.
* **Storage:** one plain file per reference, Markdown with YAML front matter
  using CSL field names, notes in the body, attachments (PDF) next to it.
  Human-readable, git- and sync-friendly, no database. The format gets a
  written, versioned specification (`docs/specs/reference-format.md`) so other
  tools can read and write it.
* **Capture:** DOI, arXiv id, ISBN lookup (Crossref, OpenAlex, arXiv; the
  existing `citations` plugin already resolves these), pasted BibTeX, dropped
  PDFs (DOI from metadata or first page, with a pure-Rust text extractor: no
  statically bundled C libraries), and a one-time importer for BibTeX, RIS and
  CSL-JSON exports from Zotero or Mendeley.
* **Organise:** collections, tags, reading status, duplicate detection by DOI
  and content fingerprint, full-text search across attached PDFs.
* **Cite:** picker and autocomplete in the editor; CSL styles (evaluate
  `hayagriva`, the Rust bibliography engine Typst uses, to replace the simple
  formatter).
* **Engine:** a standalone Rust crate with no Manang-specific assumptions,
  exposed in Manang as a system plugin (`library`), so it could be reused
  elsewhere later.
* **Theorem integration: not decided.** Theorem's plugin-first direction is
  still open. Until then, the library only commits to the open file format and
  the reusable crate; deep links into Theorem and shared plugins are revisited
  when Theorem's plan is set.

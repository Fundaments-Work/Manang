## Target: a private, invite-only beta (owner decision, 2026-10-18)

The owner will open Manang to invited users for several months, collect
feedback, and update gradually. **AI agents, collaboration and a stable system
are must-haves for that beta.** Everything below is ordered by what a real user
cannot tolerate, not by what is fun to build.

### What "ready for invited users" means

1. **Their work is never lost.** (Highest risk.) Atomic saves exist; still
   missing: crash recovery and hot exit for unsaved edits, a conflict prompt
   when an open file changes on disk (Syncthing, git, another editor), a
   backup before any destructive step (trash copies exist for discard, restore
   and plugin removal), and a corpus of realistic projects compiled in CI.
2. **Updates never break their data.** Every file format we write (project
   `manang.toml`, `settings.toml`, `keybindings.toml`, `plugins.toml`, the
   project registry, figure scenes, comments, agent transcripts) carries a
   version and has tested migrations both ways across at least one release;
   an update can be rolled back; a damaged config is set aside, never fatal
   (the plugin manager already does this).
3. **They can install it and it updates itself.** Signed installers for the
   platforms the testers use, a "beta" update channel, release notes shown after
   an update ("What's new"), and the version visible in About.
4. **We can learn from them without spying.** No telemetry. An in-app "Send
   feedback" and "Report a problem" that builds a diagnostics bundle the user
   reads and sends themselves (logs, versions, settings with secrets removed).
   Optional, opt-in crash reports later.
5. **They can get started and get unstuck.** First-run onboarding with a sample
   project, the user guide in the app (Help menu), clear errors everywhere (no
   blank screens), and a visible "something went wrong, here is what to send".
6. **AI agent v1 (must):** bring-your-own-key, safe by default (proposals only,
   nothing sent without a visible context tray, per-project opt-out), the
   writing assistant and compile-fix flows, provider presets including DeepSeek
   and local models, cost shown as an estimate, a global off switch.
7. **Collaboration v1 (must):** asynchronous git-based collaboration (Save a
   version (done), Share, Get updates, a conflict resolver, comments and review
   mode) **and real-time co-editing** (owner decision 2026-10-18: required for
   Beta 1): live sessions on one file at first, remote cursors, end-to-end
   encrypted updates through a relay, the file on disk staying plain UTF-8.
8. **Performance and stability measured**, not assumed: launch, memory,
   typing latency and recompile numbers from the real app, a desktop smoke test
   in CI, and CI itself.

### What can wait until after the first beta feedback

The managed policy layer for companies (a kill switch for AI and sharing ships
first), plugin signing, the web version, live co-editing of figures (text
files first), the reference library, a `.docx` editor.

Distribution decisions (owner, 2026-10-18): testers use **Linux, Windows and
macOS**; invitations are **per-tester private links** (a download link and an
update token per tester, revocable one by one). Still open: macOS signing and
notarisation needs an Apple Developer account (about $99/year); a Windows
signing certificate (SmartScreen warns without one); where builds, the update
manifest and the live-editing relay are hosted (the update endpoint must be
reachable by the app without an interactive login: a small static host or
object store with per-tester tokens fits; a relay needs a small always-on
service, for example a WebSocket relay on a Worker/Durable Object platform or a
VPS). Real-time collaboration therefore adds one operated service (it sees only
ciphertext) to the otherwise local-first design: record this exception in an
ADR before building it (`docs/adr/0013-live-editing.md` is drafted by the live
spike).

## The winning feature: the plugin platform (owner decision, 2026-10-18)

After studying LibrePaper (`docs/research/2026-10-18-librepaper.md`) the owner
chose where Manang must win: **the plugin scaffolding**. Everything that makes a
tool feel complete for scientists should be a plugin on a small set of
contribution points, so that we dogfood the platform and third parties can add
formats, editors and runners without touching the core.

Priorities set by the owner, in addition to the beta must-haves:

1. **Zero-install LaTeX.** Research in progress
   (`docs/research/2026-10-18-zero-install-latex.md`). For Beta 1, testers on
   Windows and macOS without TeX need an answer: the existing Tectonic sidecar
   as a consented, checksummed first-run download is the cheapest. A WebAssembly
   TeX inside our sandbox (LibrePaper's `wasm-latex` is a candidate) is the
   after-beta path and also serves the web version.
2. **Computational notebooks.** Research in progress
   (`docs/research/2026-10-18-computational-notebooks.md`): Quarto first,
   inline cells with a runner plugin, workspace trust, outputs kept out of the
   source.
3. **Live co-editing** (already a beta must-have): packages L1-L9 of the live
   spike.
4. **An Overleaf-like visual editor for every format, as ONE plugin on top of
   per-format adapters** (Typst, LaTeX, Markdown, HTML, later .docx and
   third-party formats). Research in progress
   (`docs/research/2026-10-18-visual-editor-and-document-plugins.md`). The
   working principle: the source text stays the single truth; the visual layer
   renders in place and edits through ordinary text edits, so undo, git and the
   live-editing CRDT keep working unchanged. .docx is the exception (a document
   model editor on the same contribution points).
5. **Plugin SDK as a product:** `manang plugin new` templates, a typed SDK, a
   dev loop with hot reload (the manager already watches the folder), kernel
   test harness, docs, and example plugins (a format adapter, a runner, a
   command/menu/settings plugin, an agent-tool plugin). Contribution points to
   add beyond commands, menus and settings: document types, editors, views,
   runners, importers and exporters (extends `2026-10-18-platform-v2.md`).

### Honest sequencing

These are large. They do not all fit in Beta 1, and delaying Beta 1 for them
would postpone the feedback that tells us what matters. Proposal:

- **Beta 1** (invite the first testers): stability and data safety, CI,
  installers and updates, AI agent v1, live co-editing, Share/Get updates,
  tester docs, and LaTeX that works without a TeX installation through the
  Tectonic download.
- **During the beta, in this order:** the plugin contribution points and SDK v1
  (document types and editors first, because the visual editor depends on them),
  then the visual editor for Markdown and Typst (LaTeX next), the notebook
  runner and Quarto slice, the WebAssembly TeX spike, then review by link and
  .docx.
- **Rule:** every new capability ships as a plugin on the contribution points
  (including our own first-party ones), and each gets an example in the SDK.

## The rule for running this phase

At most **two** build-heavy Claude agents at once and fewer while Antigravity is
running (a reboot happened when five agents plus three Antigravity sessions ran
together). One Chromium at a time (`flock .claude/ui.lock`). Finish and merge a
wave before starting the next. The owner's real-app testing is part of every
wave: headless checks are necessary, not sufficient.

## Desktop QA checklist (owner, `pnpm app:dev`; paste the terminal output of any failure)

1. Window: drag by the empty top bar, minimise, maximise, close, restart (size
   and position remembered); the title bar shows only the logo; the window title
   names the file and project; icon buttons turn lime on hover.
2. Menus: File/Edit/View/Go/Build/Help open with the mouse and with Alt+letter;
   resize the window below 900 px (menus fold into one button); change a
   shortcut in Settings > Keyboard shortcuts and use it.
3. Project: open a folder, create a project from a template, switch projects,
   move one to trash and restore it.
4. Typst: type and watch the preview update; no stutter; Ctrl+click the preview
   jumps to the source; Ctrl+Alt+J goes back; Export PDF.
5. PDF viewer: select and copy text, Ctrl+F, Ctrl+wheel zoom, Ctrl+= / - / 0,
   page box, outline, a link, dark pages, double-click to source.
6. LaTeX (needs TeX installed): compile, SyncTeX jump, the "No TeX found"
   message when it is missing.
7. Figures: draw each tool, connect two shapes with an arrow and move one, paste
   Mermaid text, add a formula (when the figure polish lands), change colours,
   save, copy the embed line, include it in a document.
8. Diagrams: create a `.mmd` file, save it (the `.svg` appears), Mermaid fence in
   a Markdown file.
9. Files: open an image, a PDF, a CSV and a zip (info tab, Open with system app).
10. Settings: open from a document (scoped) and from Home (all); Keyboard
    shortcuts and About views; personal dictionary.
11. Plugins: open the Plugins view (Ctrl+Shift+X), disable and enable a plugin,
    inspect permissions.
12. Versions: Save a version (Ctrl+Alt+S), open Versions, restore a file.
13. Performance feel: typing in a long document, scrolling the PDF at 400%,
    dragging 50 shapes.
Record for each: works / broken / feels slow, plus the terminal output.

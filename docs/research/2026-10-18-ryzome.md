# Ryzome (ryzome.ai): ideas to borrow

Date: 2026-10-18. Everything below is vendor-stated (no third-party coverage was
found); unverified items are marked. Ideas only: no code, assets or wording are
to be copied.

## What it is

A cloud web app (desktop-optimised): "Obsidian Canvas meets AI". An infinite
canvas where each idea is a node and edges are visible; "connecting nodes gives
the AI the upstream context". Docs: https://docs.ryzome.ai/docs/what-is-ryzome,
https://docs.ryzome.ai/faqs. Built by "the creator of Rig.rs" (the Rust LLM
library); its agents are written in Rust. One model vendor (Gemini, by choice:
1M-token window, context caching, native video/audio). Credit-metered pricing
(sources disagree), no local mode, canvases private by default. Ingestion by
drop or paste: PDF, image, YouTube, web page, text (PDFs under about 7 MB;
scanned PDFs extract poorly). Collaboration: sharing and publishing only.
Citation/provenance, export and branching mechanics are not documented
(unverified).

## What is actually distinctive

1. **Context made visible and editable as a graph:** the user steers the AI by
   drawing edges.
2. **The canvas as human-editable working memory for an agent:** generate,
   view, edit, resume (their OpenClaw loop): fix a wrong node or link missing
   context, the agent re-reads and continues.
3. **Single-hop scoping:** the AI sees only directly connected nodes, so "what
   does it see?" is answerable at a glance.
Everything else (canvas, nodes, upstream context) is familiar (Obsidian
Canvas, Miro, tldraw, NotebookLM source grounding).

## Ideas for Manang, prioritised (effort is an estimate)

- **P1 Visible, scoped AI context (3-5 days):** a collapsible context tray in
  the agent panel: chips for exactly what will be sent (selection, file,
  sources) with token counts, remove and pin, and a simple "only what is
  attached" rule. Matches the planned context chips; proposals-as-diffs stay
  the output.
- **P2 Selection-anchored AI branches (5-7 days):** a thread attached to a
  document range with sibling branches for alternative rewrites; stored as
  plain files in git (for example `.manang/threads/`), anchored like comments;
  each branch yields a diff proposal.
- **P3 Literature map (4-6 days):** library entries as cards in the figure
  studio canvas (user-drawn edges and tags first; BibTeX has no citation
  edges), select a cluster to send to the AI as context; plain scene JSON next
  to the project; no network by default.
- **P4 Source-to-claim provenance (5-8 days):** link a sentence in the draft to
  a quoted passage (PDF page and range) with a content hash; margin marks; the
  AI proposes links, the user accepts each. Not shown publicly by Ryzome: our
  differentiator.
- **P5 Spatial outline of a paper (3-5 days):** sections as cards, drag to
  reorder written back as text diffs; source files stay the truth.
- **P6 Agent working-context canvas (4-6 days):** the agent writes its plan and
  sources as an editable canvas using the figure agent tools, then resumes
  from it; only after P1.
- **P7 Ingest by drop (2-3 days):** dropping a PDF or URL creates a library
  entry and preview, locally; flag scanned PDFs without OCR.

## Avoid

Cloud-only data, credits, a single model vendor; a generic whiteboard (keep
canvases purpose-built); auto-generated nodes everywhere (everything the AI does
stays an accepted proposal); copying their UI or wording.

## Cheap experiments

1. Context tray (3 days): can testers say what the AI saw; do they use pin?
2. Reference map prototype (4 days): do two users build a map for a real paper
   unprompted?
3. Claim-source link (5 days): are links created and still resolving after
   edits?

# Pele (pele.run) as a Mermaid renderer: evaluation and revisit triggers

Date: 2026-10-18. Question from the owner: could Pele replace merman for
Mermaid diagrams? Decision: **not now; revisit when a trigger below fires.**

## What Pele is

A JavaScript/TypeScript library from the Obsidian team (kepano) that renders
Mermaid syntax to SVG: https://pele.run/, https://github.com/obsidianmd/pele,
npm `pele`. Facts checked 2026-10-18: version 1.6.0 published 2026-10-17, MIT,
zero dependencies, about 1k GitHub stars, no GitHub releases listed, 14 npm
versions. Claims support for every diagram type of Mermaid 12.1.0 (32 types in
its compatibility table; ZenUML and other plugins unsupported). Own layout and
visual style (positions differ from Mermaid; Mermaid themes and
`themeVariables` do not apply); colours come from CSS variables
(`--pele-bg`, `--pele-fg`, `--pele-line`, ...). Text measurement: canvas in a
browser, a built-in width table elsewhere (a `TextMeasurer` can be supplied).
Errors are `PeleError` with `code`, `line`, `column`. Limits: 50,000 characters
of source, 4 MB of SVG, 5,000 flowchart edges; no built-in time limit. Labels
are SVG text only (no HTML). Its own claims: "6x smaller, up to 500x faster
than Mermaid.js" (230 kB vs 1.6 MB gzip, 0.05-0.3 ms vs 6-82 ms per render).

## What we measured

On 2026-10-18, in a scratch folder (install scripts disabled), one flowchart
with a subgraph and edge labels:
- Runs in plain Node, no DOM: about 1.1 ms per render, byte-identical output
  on repeat, a syntax error reported at line 4, column 1, no `foreignObject`.
- In a browser the output is clean and modern.
- **Through our Typst SVG-to-PDF path (`typst.svg-to-pdf`, usvg/resvg) the
  same SVG renders as black blocks with the labels lost**: the SVG is built on
  CSS variables (`style="--_bg:var(--pele-bg,#fff); ... color:var(--_fg)"`,
  `font-family:var(--pele-font,sans-serif)`), which that renderer does not
  resolve. A flattening step that bakes the variables into concrete colours
  would be needed (not built, not tested; one diagram type tested only).

## Why not now

1. JavaScript: Manang's core is Rust (AGENTS.md section 2) and the planned web
   version compiles the core to wasm32. PDF export, command-line use and AI
   tools have no webview; Pele would need an embedded JS engine (a C/C++
   dependency) or webview-only use, leaving merman for export and showing two
   different pictures for one diagram.
2. The figure studio's "Mermaid to editable shapes" uses merman's node and
   edge geometry (`diagram.layout`); Pele documents no equivalent.
3. Fidelity: merman targets Mermaid 12.2 behaviour and layout; Pele is
   deliberately different, a risk for documents written for Mermaid.
4. Maturity: a day-old 1.x release against merman's weekly 0.x releases.

## What to borrow or watch

Pele's look (tonal, quiet), its responsive direction switch (a wide flowchart
turns vertical in a narrow pane), its line/column errors, and its differential
testing against Mermaid's own parser specs are all worth studying (MIT: ideas
and layout approaches can be ported with attribution).

## Revisit when any of these happens

- Pele (or a port) offers a Rust crate or a WASM build with a stable API, or
  exposes node/edge geometry.
- It publishes a CSS-variable-free output option (concrete colours), or
  ships a documented static-theme mode.
- Obsidian ships it broadly and it passes a quarter without breaking changes.
- merman stalls (no release for 3 months) or fails on diagram types we need.
- We want a second, nicer live preview renderer and accept two engines.

## If we revisit: the experiment

1. Render our 21 snapshot fixtures (`crates/manang-diagram/tests/snapshots`)
   with Pele and with merman; compare layout quality, text fit and speed on
   the same machine.
2. Build the variable-flattening step on one diagram type and check PDF output
   through `typst.svg-to-pdf`.
3. Check determinism and error positions on malformed input.
4. Decide: keep merman, add Pele as an optional preview renderer, or port its
   layout ideas into `manang-diagram`.

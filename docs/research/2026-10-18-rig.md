# Rig (rig-core) for the agentic system: evaluation

Date: 2026-10-18. The owner asked for a proper evaluation of Rig
(github.com/0xPlaygrounds/rig, crate `rig-core`) after an earlier one-line
dismissal ("too opinionated") that was written against an older version and
never tested. Probes were compile-only in a scratch folder; nothing was run
against a real LLM API.

## Verdict

Rig 0.43/0.44 (Sept-Oct 2026) was rebuilt around our concerns: a swappable HTTP
transport trait, provider-native blocks kept verbatim next to canonical ones, a
stream that is cancelled by dropping it, and wasm32 support. No blocking issue
was found. **Recommendation: adopt `rig-core` as the provider, message and
streaming layer ("hybrid i"); keep our orchestrator, policy, audit, keystore,
tool dispatch through the kernel; do not use `rig-agent`'s loop in v1; do not
use Rig vector stores.** Gate: a byte-exact replay spike (below).

## Facts (verified 2026-10-18)

- `rig-core` 0.44.0 (2026-10-07), MIT, 3.6M downloads, 8.9k stars, 91 open
  issues, backed by Playgrounds; contributors concentrated in a few people.
  Breaking changes in nearly every release (about one release every 2-3 weeks).
- 0.44 crate split: `rig-core`, `rig-http` (transport traits), `rig-reqwest`,
  `rig-agent` (the loop), `rig-cassette` (record/replay), `rig-rmcp` (pins
  rmcp ^2; our plan uses rmcp 3.5 directly), vector-store crates.
- Providers in core: Anthropic, OpenAI (Chat and Responses), DeepSeek,
  OpenRouter, Ollama, llama.cpp, Gemini, Groq, Mistral, xAI, Together, others.
  Already carries Claude Opus 5.5 ids, DeepSeek V4 names, and a forced
  `tool_choice` rejection quirk for the 5.5 family.
- **No C libraries if configured right:** default features plus `reqwest` pull
  `aws-lc-sys` (violates AGENTS.md 7.4). With `default-features = false,
  features = ["reqwest"]` plus our own reqwest 0.13 (`rustls-no-provider`) and
  rustls with `ring`: 170 crates, no `-sys` crates. Pass our own
  `reqwest::Client` (no ambient proxy, our DNS resolver, our CA bundle) through
  `with_http(...)`. Release probe: 4.58 MB vs 3.18 MB for ours (+1.4 MB, +30
  crates).
- **Lossless blocks:** each assistant block carries `native: Option<Native>`
  with the provider item verbatim (signatures, encrypted payloads); replay
  sends the native item while its fingerprint matches, gated by an `Origin`
  (api, provider, model). DeepSeek `reasoning_content` is sent back on every
  assistant message. Source-verified only: not yet diffed byte for byte.
- **Streaming and errors:** drop the stream to cancel; errors are the last
  item; `ProviderError` exposes request id, retryable, and `retry-after`.
  Rig does not retry with backoff itself: keep our `retry.rs`.
- **Policy hooks:** `HttpMiddleware` gives gateway headers and the exact final
  request body (audit and redaction); base URL is configurable.
- **Tests:** `test-utils` mock provider, `rig-cassette` record/replay, and the
  transport traits accept our own cassette transport.
- **wasm32:** `rig-core` and `rig-agent` pass `cargo check` for
  `wasm32-unknown-unknown` (browser fetch client); stronger than our crate.
- **Tool loop:** use Rig below the loop (`Model::stream` per turn); we keep the
  loop, the iteration cap, approvals, proposals, kernel calls on Rayon.
  `rig-agent` hooks (`on_dispatch` Proceed/Patch/Deny) compile and look
  workable, but where tool callbacks run relative to Rayon is unverified.
- **Embeddings:** `rig-sqlite` bundles C (forbidden), `rig-fastembed` needs
  ONNX Runtime (C++), `rig-qdrant` needs a server. Not for v1. The in-memory
  store is pure Rust; BM25 in `manang-search` stays the plan.

## What we gain and lose

Gain: 20+ providers, tracked provider API changes, wasm32, a mock and
conformance corpus. Lose: arbitrary per-block cache breakpoints (Rig has
request-level `CacheRetention` plus raw `cache_control` passthrough), control
of the wire model, and exposure to a fast-breaking pre-1.0 API (mitigate: pin
exactly, keep every Rig type behind an adapter crate, golden/cassette tests).

## Migration (least waste)

Keep `manang-agent-core` (policy, audit, redaction, prices, presets),
`manang-keystore`, our transport (loopback resolver, no ambient proxy, no
redirects) and `retry.rs` wrapped as an `HttpClientExt`. Replace the bodies of
`manang-agent-providers` adapters (`anthropic.rs`, `openai.rs`, `driver.rs`,
`sse.rs`) with a Rig-backed `Provider`. Re-point the cassette tests as goldens.
Delete our SSE parser and fuzz target once parity holds.

## Gate: the replay spike (2 days)

Replay a recorded Anthropic thinking plus `tool_use` conversation and a
DeepSeek `reasoning_content` conversation through Rig's encoder and diff the
request bytes against our `request_body()`; confirm mid-stream error and
cancel behaviour over our cassette transport; confirm the retry wrapper and
loopback resolver plug in. Pass means proceed with the migration; fail means
keep the in-house crates and record why.

## Open decisions

1. Is the spike the gate? (proposed: yes)
2. Rig's `Message` as the on-disk transcript type, or keep our `ContentBlock`
   and map both ways? (proposed: keep ours on disk, map at the adapter)
3. Is request-level cache control enough?
4. Revisit `rig-agent` after the orchestrator exists.
5. Exit plan: keep our adapters buildable behind a feature.
6. Keep our own MCP server on `rmcp` 3.5 (not `rig-rmcp`).
7. No semantic search in v1.
